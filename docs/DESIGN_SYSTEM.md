# Design System Companion

Everything the [Stitch-format DESIGN.md](../DESIGN.md) cannot hold.

## 1. Why the split

[DESIGN.md](../DESIGN.md) is machine-consumed. It is regenerated by the `impeccable` skill in a fixed six-section Google Stitch shape (frontmatter token block, then Overview, Colors, Typography, Elevation, Components, Do's and Don'ts), and that skill forbids extra sections because anything else in the file makes the generator drop or mangle it.

That format has no room for the things that actually make a design system hold together under load: the spacing rationale, the control geometry rules, the state layer contract, motion policy, the browser support floor, iOS hardening notes, or the anti-pattern list with reasons. Those live here.

Read them together:

| File | Holds | Audience |
|---|---|---|
| [DESIGN.md](../DESIGN.md) | Colour roles, type scale, elevation, component tokens. Six sections, regenerable. | Machine, then humans |
| [docs/DESIGN_SYSTEM.md](DESIGN_SYSTEM.md) | Spacing, control geometry, state layer, motion, responsive rules, browser floor, iOS hardening, anti-patterns, contribution checklist. | Humans making changes |
| [PRODUCT.md](../PRODUCT.md) | What the product is and who it serves. | Everyone, first |
| [docs/Architecture.md](Architecture.md) | How the system is wired. | Engineers |
| [docs/Rules.md](Rules.md) | Security rules and code standards. | Engineers |

If a rule is enforced by a test, the test is named here. Documentation that cannot fail is a wish. `tests/unit/designTokens.test.ts`, `designSystem.test.ts`, and `motionTokens.test.ts` read `tailwind.config.js` and `src/index.css` directly and fail the build when these rules drift.

## 2. The spacing system

### 2.1 4pt base

The scale is 4 / 8 / 12 / 16 / 24 / 32 / 48 / 64 / 96. Not 8pt.

8pt is too coarse for this product. Text fields want 16px padding, dense controls want 12px horizontal padding, and a chip wants 4px between an icon and its label. On an 8pt base you end up inventing 12px anyway and then you have two grids.

Tailwind's numeric scale is already 4pt based, so the numbers are the scale. The names below exist so component padding reads as a role rather than as an arithmetic result. `p-6` tells you nothing six months later. `px-control-x` tells you what it is for.

### 2.2 Semantic names

| Token | Value | Where it belongs |
|---|---|---|
| `3xs` | 4px | Icon to label inside a dense control |
| `2xs` | 8px | Between related inline items |
| `xs` | 12px | Tailwind default |
| `sm` | 16px | Tailwind default. Field padding, base gutter |
| `md` | 24px | **Custom.** Card padding desktop, section gap, control-x |
| `lg` | 32px | Tailwind default |
| `xl` | 48px | Tailwind default. The touch floor |
| `2xl` | 64px | Tailwind default. Top app bar height |
| `3xl` | 96px | Tailwind default. Hero section padding |

### 2.3 Component tokens

| Token | Value | Purpose |
|---|---|---|
| `control-y` | 12px | Vertical padding inside a 48px button |
| `control-x` | 24px | Horizontal padding, default button |
| `control-x-sm` | 12px | Horizontal padding, small button |
| `control-x-lg` | 32px | Horizontal padding, large button |
| `field-x` | 16px | Text input horizontal padding |
| `field-y` | 16px | Text input vertical padding |

### 2.4 `gap` over margins

Prefer `gap-*` on a flex or grid container over `margin-*` on the children. Three reasons, all practical:

- Reversing a vertical stack with `flex-col-reverse` does not reverse margins. Gaps do the right thing.
- Collapsing adjacent margins is a rule the reader has to know. `gap` has no such rule.
- Margins leak: a child's bottom margin reaches outside its parent and moves something else on the page. Gaps cannot.

### 2.5 `md` is not a Tailwind default

Worth stating plainly, because it has already cost this codebase a bug.

`md` reads like a Tailwind default. It is not. In stock Tailwind, `md` is only a breakpoint variant (`md:flex`), and there is no `p-md`, `gap-md`, or `space-y-md`. Those classes silently do nothing, because Tailwind emits no rule for a key that does not exist.

`tailwind.config.js` declares `spacing.md: 1.5rem` explicitly. 24px is the single most referenced value in this design system (desktop card padding, section gap, and `control-x` all resolve to it) and it had no semantic name at all, so every call site spelled it `p-6`. Adding it is what lets the component tokens read as roles.

The same trap applies to `lg`, `xl`, and `2xl`: those are defaults for spacing but also breakpoint variants. `gap-lg` works, `lg:gap-4` is a breakpoint. Read the colon.

## 3. Control geometry

| Surface | Height | Token |
|---|---|---|
| Button, every size | 48px | `min-h-control` |
| Select, tab | 48px | `min-h-control` |
| Text field, textarea | 56px | `min-h-control-lg` |
| Dense desktop data surface only | 40px | `h-control-sm` |

**48px is a floor, not a preference.** It applies to every button size including `sm`. Material's own button is 40dp; our product constraint is stricter than the spec's, because the primary use is a one-handed tap on whatever phone a volunteer owns at a venue door. `sm` tightens horizontal padding and type size. It never reduces height.

56px for text fields is Material's field height, and it is where the extra room belongs because typing accuracy beats density in a form.

### 3.1 44px is banned

44px is Apple's HIG minimum and it appears in most design system references. It is not on this scale and must not be used. Off-scale values are how a codebase ends up with 66 distinct padding signatures across 203 buttons, which is exactly what the audit found. If a value is not in the table above, it does not exist.

Where a smaller height is genuinely needed (a dense admin table row), use `h-control-sm` (40px) and accept that it is documented as a desktop-only exception, not a new floor.

## 4. The state layer

Material 3 models interaction as one overlay element whose opacity changes per state, rather than per-variant `hover:bg-black/5 active:bg-black/10` class strings. This project implements it once in `src/index.css` as `.md-state-layer`, which is why the design system needs no class-variance-authority. Interaction logic is written one time and every component inherits it.

### 4.1 Opacity variables

| Variable | Default | Meaning |
|---|---|---|
| `--md-state-hover-opacity` | 0.08 | Pointer hover |
| `--md-state-press-opacity` | 0.12 | Active press |
| `--md-state-focus-opacity` | 0.10 | Keyboard focus |
| `--md-state-selected-opacity` | 0.12 | Selected tab, active nav item |
| `--md-state-disabled-opacity` | 0.38 | Disabled or `aria-disabled` |
| `--md-state-layer-color` | `25 28 32` | Overlay colour, on-surface by default |

Hover is gated behind `@media (hover: hover) and (pointer: fine)`. A sticky `:hover` on touch leaves the overlay latched on after a tap, which reads as a stuck button.

### 4.2 Filled surfaces override the overlay

A filled button carries light text, so its overlay must be light too. Otherwise the hover state on `bg-primary` is near invisible.

| | Light surfaces (default) | `data-surface="filled"` |
|---|---|---|
| `--md-state-layer-color` | `25 28 32` | `255 255 255` |
| `--md-state-hover-opacity` | 0.08 | 0.16 |
| `--md-state-press-opacity` | 0.12 | 0.24 |

### 4.3 Usage

One line, applied to any interactive surface. The only per-variant work is setting the overlay colour when the surface is filled.

```tsx
<button className="md-state-layer bg-primary text-on-primary data-[surface=filled]" />
```

Do not hand-roll hover, active, focus, or disabled opacity classes. If a surface needs different numbers, set the variable; do not reimplement the mechanism. `tests/unit/designSystem.test.ts` asserts that raw `hover:bg-*` and `active:bg-*` strings only appear inside the primitives layer.

## 5. Elevation

| Level | Token | Value | Used by |
|---|---|---|---|
| 0 | `elevation-0` | none, plus a 1px `outline-variant` hairline | Dashboard panels, tables, registration steps. The resting state |
| 1 | `elevation-1` | `0 1px 2px 0 rgb(0 0 0 / .06), 0 1px 3px 1px rgb(0 0 0 / .04)` | Hover on an interactive card, elevated button |
| 2 | `elevation-2` | `0 2px 4px 0 rgb(0 0 0 / .07), 0 4px 8px -1px rgb(0 0 0 / .06)` | Menus, popovers, dropdown panels |
| 3 | `elevation-3` | `0 4px 8px -2px rgb(0 0 0 / .09), 0 8px 16px -4px rgb(0 0 0 / .07)` | Dialogs, bottom sheets, check-in scanner overlay |
| 4 | `elevation-4` | `0 8px 16px -4px rgb(0 0 0 / .10), 0 16px 28px -8px rgb(0 0 0 / .08)` | A certificate canvas element under manipulation |
| 5 | `elevation-5` | `0 12px 24px -6px rgb(0 0 0 / .12), 0 24px 40px -12px rgb(0 0 0 / .09)` | FAB, scanner chrome |

Alphas sit below Material's reference values deliberately. This is a light, high-contrast, daylight-readable product, and a shadow you can clearly see is a shadow that has failed at its job.

### 5.1 The Level 0 Rule

Panels, tables, and page sections rest at level 0. Elevation appears on interaction (level 1) and on transient surfaces (levels 2 to 5).

A non-interactive panel that lifts on hover is a false affordance: it promises the panel responds to being touched, and it does not. This is the single most common misuse of elevation in this codebase's history.

**The One-Tone Rule.** Nested surfaces step exactly one tone (`surface` to `surface-container-low` to `surface-container`). A bordered box inside a bordered box is not a nested card; use a background tint or a divider.

| Token | Value | Where |
|---|---|---|
| `rounded-xs` | 4px | Chips, tags, the smallest element |
| `rounded-sm` | 4px | Same as xs |
| `rounded` (DEFAULT) | 8px | Buttons, inputs, inline controls. The control floor |
| `rounded-md` | 12px | Compact surfaces, form fields |
| `rounded-lg` | 12px | Dashboard panels |
| `rounded-xl` | 16px | Event discovery cards |
| `rounded-2xl` | 28px | Dialogs and bottom sheets on mobile |
| `rounded-3xl` | 36px | Rare. Reserved |
| `rounded-full` | 9999px | Status badges, avatars, icon-only buttons |

Larger radius for larger surface is the pattern. A 28px radius on a 48px button reads as a mistake; a 4px radius on a full-width card reads as unfinished.

## 7. Colour roles

Colour lives in [DESIGN.md section 2](../DESIGN.md#2-colors). This file does not repeat it. The short version:

- Components reference roles (`bg-surface-container-low`), never brand names (`bg-gray-50`).
- Fills are tone 40 of their ramp (`primary #0b57d0`, `error #b3261e`, `success #186a3b`), not the brand hexes, because the brand hexes fail WCAG AA against white text at 16px.
- Amber is never a fill. It is a container pair (`#fce8b2` / `#3d2700`) at 11.64:1.

**Contrast is enforced by tests, not by review.** `tests/unit/designTokens.test.ts` computes the WCAG relative-luminance ratio for every `on-*` and container pair straight out of `tailwind.config.js` and asserts the documented floor. Editing a token to a darker fill fails the test and prints the ratio it actually produced. Do not weaken the assertion to accommodate a colour you like.

## 8. Motion

### 8.1 Duration scale

| Token | Value | Use |
|---|---|---|
| `short2` | 100ms | Micro-feedback, state layer tint |
| `short4` | 200ms | Small surfaces entering |
| `medium2` | 300ms | State changes |
| `medium4` | 400ms | Card reveals |
| `long2` | 500ms | Full surfaces entering |
| `exit` | 180ms | Anything leaving |

### 8.2 The three emphasized curves

| Token | Value | Use |
|---|---|---|
| `emphasized-decelerate` | `cubic-bezier(0.2, 0, 0, 1)` | Something entering. Fast start, settle |
| `emphasized-accelerate` | `cubic-bezier(0.05, 0.7, 0.1, 1)` | Something leaving. Slow start, quick exit |
| `emphasized-standard` | `cubic-bezier(0.3, 0, 0.8, 0.15)` | Something moving within the screen |

They are mirrored as CSS custom properties in `src/index.css` (`--motion-ease-*`, `--motion-duration-*`) so state-driven animations outside Tailwind utilities use the same values.

### 8.3 Exits run at roughly 75% of entrances

`exit` is 180ms against an entrance of 240ms or more. An exit is a confirmation, not an event. The user has already decided to leave; making them wait for a full entrance duration to find out is a small tax on every navigation.

`tests/unit/motionTokens.test.ts` asserts that `exit / base` sits in the range 0.5 to 0.8.

### 8.4 Banned

- **No bounce, no elastic, no overshoot.** Both read as dated. They also communicate a physical object where there is none.
- **Never animate layout properties.** No `width`, `height`, `top`, `left`, `margin`, or `padding` transitions. Animate `transform` and `opacity` only. Layout animation forces reflow on every frame and drops frames on the low-end Android phones that half our attendees own.
- **`prefers-reduced-motion` is mandatory, not optional.** `src/index.css` carries a global `reduce` block that collapses animation and transition durations. Loading indicators are explicitly exempted from the blanket kill (they become a slow luminance breath, no movement) because a frozen spinner reads as a broken interface, and the accessible name still carries the state.

## 9. Responsive and breakpoints

Mobile first. Base styles target the phone; wider viewports are progressive enhancement.

| Variant | Width | What it is for |
|---|---|---|
| base | 0 | Phone. Every layout starts here |
| `sm` | 640px | Large phone landscape, small tablet. Two-column grids begin |
| `lg` | 1024px | Tablet landscape, small laptop. Sidebars, three-column grids |
| `xl` | 1280px | Desktop. Max-width containers, dense data tables |

`tailwind.config.js` does not override `screens`, so these are Tailwind's defaults. They are the MD3 compact (0 to 599), medium (600 to 839), expanded (840 to 1199), and large (1200 plus) breakpoints expressed in px.

### 9.1 The gutter rule

| Breakpoint | Gutter |
|---|---|
| base | 16px (`px-4`) |
| `sm` | 24px (`px-6`) |
| `lg` and up | 32px (`px-8`) |

**The top bar, the page title, and `<main>` MUST share the same gutter.** They are three separate elements in the DOM and nothing in CSS ties them together, so it is possible, and has happened, for one to drift while the other two do not. The result is a visibly ragged content edge that most reviewers read as a browser bug.

This was the one thing already correct in this codebase. Do not "fix" it independently in a new screen.

## 10. Browser support and iOS hardening

### 10.1 The floor

| Browser | Minimum | What sets it |
|---|---|---|
| Safari / iOS Safari | 15.4 | `dvh` units, `:focus-visible`, CSS nesting-free syntax |
| Chrome / Edge | 108 | `dvh` units |
| Firefox | 101 | `dvh` units |

`dvh` is the binding constraint across all three, so it sets the floor. This is pinned in the `browserslist` field in `package.json` so autoprefixer and Vite's build target agree with it. Vite 6's own default target list is far older and would have produced CSS nobody on this floor needs, while saying nothing about what we actually support.

Everything below assumes a phone in one hand, in sunlight or in a dim hall, on a metered connection.

### 10.2 `100vh` is wrong on iOS

`100vh` on iOS Safari resolves to the **tallest** viewport, the one you get with the browser toolbar collapsed. Any full-height surface built on it overflows by roughly 60 to 100px whenever the toolbar is showing, which cuts off the last table row and the bottom of every form.

Use the `.min-h-page` family, declared in `src/index.css`:

```css
.min-h-page { min-height: 100vh; min-height: 100dvh; }
```

That is a declaration pair, not two Tailwind classes on one element, and the reason matters. Tailwind resolves competing utilities by stylesheet order, not class-attribute order, so `min-h-screen min-h-dvh` silently picks whichever the compiler happened to emit last. The cascade here is explicit and the `vh` fallback is guaranteed.

There is also `.h-page` and `.max-h-page` with the same pairing.

### 10.3 Safe areas

Every iPhone since the X has a notch or a home indicator. `position: fixed` elements ignore both by default, so a bottom-anchored FAB renders underneath the home indicator and becomes partly untappable, and a full-height overlay tucks its own close button under the sensor housing.

Four utilities in `src/index.css`, required on **every fixed or bottom-anchored surface**:

| Class | Applies |
|---|---|
| `.safe-t` | `padding-top: env(safe-area-inset-top, 0px)` |
| `.safe-b` | `padding-bottom: env(safe-area-inset-bottom, 0px)` |
| `.safe-x` | Left and right `env(safe-area-inset-*)` |
| `.safe-b-offset` | `bottom: calc(var(--fab-offset, 16px) + env(safe-area-inset-bottom, 0px))` for floating elements that need to clear the indicator while keeping their own design offset |

Before these existed the codebase had zero `safe-area-inset` occurrences against 19 fixed surfaces.

### 10.4 Do not strip `appearance` from `<select>` on mobile

`appearance: none` on a `<select>` removes the platform control, and with it the native iOS wheel picker and the Android bottom sheet. Those are better than anything hand-built, and the audience is a student on whatever phone they own.

Keep `appearance` on selects. Custom chevrons are fine as an addition, never as a replacement for the native affordance.

### 10.5 Native `<dialog>` exit animations

The shared `Modal` is built on the native `<dialog>`, which supplies the focus trap, Escape handling, inert background, and `::backdrop` for free.

Its **exit** animation cannot rely on `transition-behavior: allow-discrete`. That property needs Chrome 117, Safari 17.5, and Firefox 129, which is well above our floor of Safari 15.4. Without it, `display: none` applies immediately and the browser never renders the closing frame, so the dialog vanishes with no transition at all.

Drive the exit from React instead: set `open` to false, wait for the transition duration, then call `el.close()`. That works on every browser in the support matrix. Do not reach for `allow-discrete` until the floor moves past Safari 17.5.

## 11. Accessibility

WCAG 2.2 AA is the target for all public and admin interfaces ([PRODUCT.md](../PRODUCT.md)).

| Concern | Rule |
|---|---|
| Touch targets | 48px minimum, no exceptions in mobile UI |
| Text legibility | 14px floor for body and interactive label copy |
| Form controls | **16px minimum**, above the legibility floor |
| Line length | 65 to 75 characters maximum for paragraphs |
| Keyboard | Every action reachable and operable by keyboard alone |
| Focus | 2px `primary` ring at 2px offset, visible against `surface` |
| Errors | Inline text, wired via `aria-describedby`, never colour alone |

**Why form controls are 16px and not 14px.** iOS Safari zooms the viewport on focus for any input below 16px, which yanks the layout sideways mid-form. On a venue wifi that is also dropping packets, a zoomed viewport mid-entry is the worst possible failure. `DESIGN.md` typography uses 14px for labels and status badges, which do not trigger focus zoom, so there is no conflict.

**Keyboard paths.** Modal Escape closes and returns focus to the trigger. Tab order follows DOM order, so visual order and DOM order must not diverge. A `<button>` with no `type` inside a `<form>` submits it, which is why the Button primitive defaults to `type="button"`.

**Roving tabindex on tab lists.** A tab strip is one tab stop, not five. The active tab carries `tabIndex={0}` and its siblings `tabIndex={-1}`, with arrow keys moving the selection. `src/components/UI/Tabs.tsx` implements this. Without it, a keyboard user tabs through every tab in the strip before reaching the panel, which is the classic ARIA tabs mistake.

**`eslint-plugin-jsx-a11y` is on, at `warn`.** Every rule is configured as `warn` rather than `error` because the codebase carries roughly 195 raw buttons and a real backlog of non-compliant markup that is being migrated file by file. Promoting them to errors would fail the build on day one and block every unrelated change. Treat the warning count as a ratchet: it should go down, and a PR that adds new warnings while touching a file should fix them in that file.

## 12. Motion embargo

**Motion must never gate the venue check-in queue.**

The check-in loop is the single most latency-sensitive path in the product. A volunteer scans a QR code at a door, in a line, with people waiting. PRODUCT.md's Anti-references section lists "heavy decorative animations that degrade performance or stall fast venue check-in lines" as a thing this product is not.

Consequences, all binding:

- No entrance animation on the check-in confirmation path. The result renders immediately.
- No staggered reveal on the attendee list while a scan is in flight.
- The scan-to-confirmation loop stays non-blocking: the camera decoder and the Firestore write must not sit behind a transition, a debounce, or an animation frame wait.
- If motion and speed ever conflict on this path, motion loses.

Motion elsewhere in the product is welcome. The public event page hero is the one orchestrated sequence and it is allowed, because an attendee arriving from a shared link is reading a flyer and a headline arriving with it is a welcome.

## 13. Anti-patterns

These are absolute bans, inherited from PRODUCT.md's Anti-references and DESIGN.md section 6.

| Banned | Why |
|---|---|
| **Side-stripe borders** (`border-left: 3px solid ...`) | They read as an iOS swipe-back affordance. On iOS the left edge of the screen means "go back", and a coloured stripe there competes with a system gesture. Use a full border, a pill badge, or a background tint |
| **Gradient text** (`background-clip: text`) | It is a screenshot filter, not a hierarchy tool. It also fails contrast in the middle of the gradient where the blend lands unpredictably. Headings use solid high-contrast ink |
| **Glassmorphism as a default** (`backdrop-blur` on surfaces) | Blur costs GPU time on the low-end phones that half our attendees own, and it wrecks text contrast over photographs. Legitimate exactly once: over a known-dark image with a solid scrim behind the text |
| **The hero-metric template** (a row of four equal big-number boxes on every dashboard) | An unearned metric box is decoration. Ship a stat only where it changes a decision, and pair it with the thing it is a rate of |
| **Walls of identical cards** | The same icon, the same corner radius, the same `shadow`, six times, is a template, not a layout. Differentiate by hierarchy: the first item is the one you act on |
| **Modal as first thought** | A modal interrupts, breaks browser back-navigation, and traps focus. Inline progressive disclosure works better on mobile. Reach for the modal when the action is genuinely modal: destructive, multi-field, or it must not be interrupted |

Two more that are not on the list above but are enforced by `tests/unit/designSystem.test.ts`:

- **Nesting cards inside cards.** Use a background tint or a divider for the inner grouping.
- **Hand-rolled interaction states.** If you are writing `hover:bg-*` or `active:bg-*` outside `src/components/UI/`, you are reimplementing the state layer that already exists.

## 14. Adding a component

The order matters. Each step fails loudly if you skip it.

1. **Tokens before hex.** Check `tailwind.config.js` for a role that already means what you need. If nothing does, add the token there, with the contrast rationale in a comment, and let `tests/unit/designTokens.test.ts` check it. Never write a raw hex in a component.
2. **Primitive before raw HTML.** If `src/components/UI/` already has something close, extend it. Raw `<button>`, `<input>`, or `<select>` is only allowed inside that directory. A new primitive needs `forwardRef`, spreads `...rest` onto the DOM node, and a typed props interface that extends the native attributes.
3. **Geometry from the token layer.** `min-h-control`, `px-control-x`, `rounded`, and friends. No hand-written `py-2 px-4`. If the existing tokens cannot express the control you need, that is a token addition, not a one-off.
4. **State layer, not hand-rolled hover.** Add `md-state-layer` to the base class string and set `data-surface="filled"` if the surface carries light text. Do not write variant-specific hover classes.
5. **Tests for the gate.** A new utility or token goes in `tests/unit/`. A new component that renders needs a test in `tests/dom/` (`bun run test:dom`, jsdom project, see [tests/dom/README.md](../tests/dom/README.md)). A new service method or data transformation needs a unit test in `tests/unit/`.
6. **Run the five gates.** `bun run typecheck`, `bun run lint`, `bun run test:unit`, `bun run build`, and `bun run test:rules` if you touched `firestore.rules` or `storage.rules`. CI runs all five; see [.github/workflows/ci.yml](https://github.com/gdgdavao/teamapo-hub/blob/main/.github/workflows/ci.yml) and [CONTRIBUTING.md](../CONTRIBUTING.md).
7. **Document it here** if it introduced a rule rather than following one.

The primitives that already exist, and that you should reach for before writing anything new: `Button`, `Card`, `Input`, `Select`, `Textarea`, `Badge`, `Modal`, `Tabs`, `DataTable`, `EmptyState`, `ProgressBar`, `Skeleton`, `SimpleBarChart`, `Field`, `LoadingSpinner`, `ConfirmationModal`, `WalkInRegistrationModal`, `ForceCheckInModal`, `Reveal`, `TrendRangeToggle`, `DashboardStatStrip`, `DashboardTrendPanel`, `DashboardShell`, `AppToaster`.

## 15. Toast Notifications & Feedback Alerts

TeamApo Hub standardizes feedback notifications across the entire platform via `react-hot-toast` and the primitive `<AppToaster />` mounted in `src/main.tsx`.

### 15.1 Physical Scene & Viewport Adaptation
- **Mobile (< 640px)**: Bottom-center placement (`bottom-center`) with `env(safe-area-inset-bottom)` offsets so notifications remain in the user's thumb zone during on-site camera check-ins and walk-ins, without colliding with the iOS home indicator or camera cutouts.
- **Desktop (≥ 640px)**: Bottom-right alignment (`bottom-right`) adhering to Google Material 3 snackbar guidelines.
- **Layering**: Pinned at `z-index: 1400` so toasts float cleanly above modals (`z-50`) and full-screen camera viewfinders.

### 15.2 Surface & Semantic Tokens
- **Banned**: Side-stripe colored borders (`border-left: 3px solid ...`).
- **Success**: `bg-success-container` with `text-on-success-container` and tone-40 icon `#186a3b`.
- **Error**: `bg-error-container` with `text-on-error-container` and tone-40 icon `#b3261e`.
- **Blank / Info**: `bg-secondary-container` with `text-on-secondary-container` and brand blue icon `#4285f4`.
- **Loading**: `bg-surface-container-high` with `text-on-surface` and primary spinner.
- **Elevation & Geometry**: `rounded-xl` (12px), full 1px tonal border, M3 elevation-2 drop shadow, `-webkit-backdrop-filter: blur(12px)`.

### 15.3 Dismiss Affordance & Accessibility
- **WCAG 2.2 AA Tap Targets**: Dedicated close button with `min-h-control min-w-control` (48px x 48px target) and `aria-label="Dismiss notification"`.
- **Tap-to-Dismiss**: Tapping anywhere on a non-loading toast card immediately dismisses it.
- **Announcements**: Errors announce assertively (`role="alert"`, `aria-live="assertive"`, 6s duration); successes and notices announce politely (`role="status"`, `aria-live="polite"`, 4s duration).
